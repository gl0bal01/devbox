# Services

Each directory here is one Docker Compose project. `setup.sh` mirrors it into `~/docker/<service>/` and starts nothing. The helpers `start-all.sh` and `stop-all.sh` run the projects in the order listed in `DEVBOX_SERVICES` (`scripts/lib/devbox-contract.sh`). The design rationale is in [ARCHITECTURE.md](../ARCHITECTURE.md).

```
services/
├── traefik/                      reverse proxy + docker-socket-proxy
│   ├── docker-compose.yml        base: port 80 on ${TAILSCALE_IP}, dashboard router
│   ├── docker-compose.https.yml  overlay: port 443, ovh.env, ACME volume `letsencrypt`
│   ├── docker-compose.lock.yml   generated digest lock
│   ├── traefik.yml               static config, HTTP mode
│   ├── traefik.https.yml.template  static config, HTTPS mode (rendered over traefik.yml)
│   └── dynamic/                  file-provider middlewares (headers, allowlist, HSTS)
└── ollama-openwebui/             Ollama + Open WebUI
    ├── docker-compose.yml        base: routers for ai.internal and ollama.internal
    ├── docker-compose.https.yml  overlay: TLS routers for ai.<domain>, ollama.<domain>
    ├── docker-compose.gpu.yml    overlay: NVIDIA GPU reservation for Ollama
    ├── docker-compose.lock.yml   generated digest lock
    ├── .env.template             rendered once into .env
    └── .env.example              documents the .env keys (not installed)
```

## How the files are used

| File | Handling |
|---|---|
| `docker-compose.yml` | Tracked and mirrored on every run. Pins tags, never digests. |
| `docker-compose.https.yml` | Chained when `ENABLE_HTTPS=true` |
| `docker-compose.gpu.yml` | Chained when `DEVBOX_GPU=nvidia` |
| `docker-compose.lock.yml` | Always chained last. Generated by `scripts/update-images.sh --apply`; never edit it by hand. |
| `traefik.yml` | Mirrored. In HTTPS mode, replaced by the rendered `traefik.https.yml.template` (whitelist: `$ACME_EMAIL`). |
| `dynamic/middlewares-*.yml` | Mirrored. Traefik watches the directory. |
| `dynamic/dashboard-auth.yml`, `dynamic/ollama-auth.yml` | Installed only. Rendered on every run from `~/docker/.secrets/*.txt`, and again by `rotate-ollama-auth.sh` and `restore.sh`. Mode 0640: Traefik reads them through the operator's group (`group_add: ${DEVBOX_GID}`). |
| `ollama-openwebui/.env.template` | Rendered once into `.env` (whitelist: `$WEBUI_SECRET_KEY $ENABLE_SIGNUP`) |
| `traefik/ovh.env` | Installed only, HTTPS mode. Copied from `~/.config/devbox/ovh.env`. |
| volume `traefik_letsencrypt` | HTTPS mode. Traefik creates and owns `acme.json` in it, and `backup.sh` archives it with the other volumes. |

The mirror (`rsync --delete`) skips dotfiles, `ovh.env`, `letsencrypt/`, `logs/`, `dynamic/*-auth.yml` and `*.template`. Those paths are never copied over or deleted. A legacy host-side `letsencrypt/` from older installs is left in place, unused.

## The `.env` file

Each installed service directory has a `.env`, mode 0600. Compose reads it automatically. `setup.sh` manages a few keys in it and leaves every other line alone:

| Key | Service | Set by setup |
|---|---|---|
| `COMPOSE_FILE` | all | Every run: `docker-compose.yml[:docker-compose.https.yml][:docker-compose.gpu.yml]:docker-compose.lock.yml` |
| `TAILSCALE_IP`, `DEVBOX_GID` | traefik | Every run (`restore.sh` keeps the current host's values) |
| `DOMAIN` | ollama-openwebui | Every run in HTTPS mode |
| `OLLAMA_CPUS` | ollama-openwebui | Only if absent: `min(nproc, 4)` |
| `WEBUI_SECRET_KEY`, `ENABLE_SIGNUP` | ollama-openwebui | Once, at first render. `ENABLE_SIGNUP` only seeds the first start: Open WebUI then keeps the setting in its database (Admin Panel > Settings > General). |

Operator tunables for Ollama are `OLLAMA_MEM_LIMIT` (default `8g`), `OLLAMA_CPUS`, `OLLAMA_KEEP_ALIVE`, `OLLAMA_NUM_PARALLEL`, `OLLAMA_MAX_LOADED_MODELS` and `OLLAMA_CONTEXT_LENGTH` (see `services/ollama-openwebui/.env.example`). Apply them with `start-all.sh`.

Because `COMPOSE_FILE` is in `.env`, a plain `docker compose ps|logs|up -d` inside `~/docker/<service>/` uses the same chain as the helpers, digest lock included.

## Conventions

- **Project name.** Set a top-level `name:` equal to the directory name. Volume names (`<service>_<volume>`) and the backup discovery label depend on it.
- **Networking.** Only Traefik publishes ports, and only on `${TAILSCALE_IP:?...}`. Other services use `expose:` on the external `proxy-net` network and are reached through Traefik routers.
- **Fail closed.** Use `${VAR:?message}` for anything whose absence would be unsafe: a bind address or a secret.
- **Hardening.** Every service sets `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]` (add back only what is needed), `mem_limit`, a `healthcheck`, a `container_name` and `restart: unless-stopped`. `security-check.sh` verifies these on the running containers.
- **Routing.** Use `traefik.enable=true`, one router per host, and `entrypoints=web` (`websecure` in the HTTPS overlay). The entrypoints already apply the security headers and the Tailscale allowlist. Basic auth is per router (`ollama-auth@file`, `dashboard-auth@file`).
- **Logging.** Do not add per-service logging blocks. `/etc/docker/daemon.json` sets rotation host-wide.
- **Docker API.** Only `docker-socket-proxy` mounts the Docker socket, read-only.

## Adding a service

1. Add the service to `scripts/lib/devbox-contract.sh`: a `DEVBOX_SERVICES` entry (after its dependencies), plus `DEVBOX_CONTAINERS_<svc>` and `DEVBOX_HOST_<svc>` (dashes become underscores). Add volume keys to `DEVBOX_BACKUP_EXCLUDE_VOLUMES` only if they hold re-creatable data.
2. Create `services/myservice/docker-compose.yml` following the conventions above. Its `Host()` rules must match the contract hosts exactly.
3. Generate the lock: `scripts/update-images.sh --apply`.
4. Optionally add `docker-compose.https.yml`. If the service needs generated secrets, add a `.env.template` and a matching `render_once` call in `setup.sh`.
5. Run `make test`. `tests/contract/contract.bats` checks the project name, container names, hosts, hardening, published ports and lock. `scripts/ci/check-compose-config.sh` validates every chain.
6. Run `make ci` for a real install.
7. Document the new host for clients (`/etc/hosts` line in [README.md](../README.md)).

Backups, `security-check.sh`, `status.sh` and `diagnose.sh` pick up the new service from the contract with no further changes.

## Updating images

- **Within a pinned tag:** a monthly CI job runs `scripts/update-images.sh --apply`, smoke-tests the result and opens a pull request. Run the same command locally whenever you need it.
- **Minor or major bump:** edit the tag in the base `docker-compose.yml`, run `scripts/update-images.sh --apply`, then run `make ci` and commit both files.
- **Patch-pinned images** (`ollama/ollama`, `tecnativa/docker-socket-proxy`, whose upstreams publish no minor tags) move only when you bump them.

Locks pin `repo:tag@sha256:<multi-arch index digest>`, so the same lock works on amd64 and arm64.
